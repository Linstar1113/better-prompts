# 三域终版骨架

选域判定见 `questionnaire.md` §三。这里只给**终版怎么写**。通用规则（改动白名单、长度闸门、标注语法）在 `SKILL.md` 第 3 步，本文件不重复。

## 一、生图

| 用 | 不用 |
|---|---|
| 画面清单（主体、动作、环境、光线、材质）+ 构图/比例 + 风格特征 + 负面内容 | 抽象形容词堆叠（"高大上""有感觉"） |
| 模型可解析的参数（比例、数量、参考图、保持项） | 文学化比喻、情绪描述代替画面 |

骨架：

```text
画面：<主体>，<动作/状态>，<环境>，<光线>，<材质/细节>
构图：<比例>，<主体位置>，<留白/文字区>
风格：<配色>，<质感>，<参考方向>
避免：<不想要的元素>，<不想要的风格>
参数：<数量>，<分辨率>，<是否有参考图及必须保持的元素>
```

范例：

```text
画面：单支白色陶瓷马克杯，斜 45° 悬空，浅灰无缝背景，顶部柔光箱打光，杯口有细微高光，杯壁哑光釉面可见
构图：1:1，主体居中略偏下，四周各留 15% 安全区，右上角不放任何元素（后期加文字）
风格：低饱和灰白调，商业产品摄影质感，无道具无场景
避免：文字水印、logo、人手、杂乱背景、高饱和撞色
参数：1 张，2048×2048
```

要点：**"要什么"和"不要什么"分开写**，负面内容单独一行；参考图必须写成"必须保持 X 不变"。

**严禁写成"以随附参考图为准"却不确认用户是否真有图**——模型会不知道该跟什么。两种情况分写：

- 用户**有**参考图 → 写「外观/LOGO/配色以参考图为准，必须保持不变」，并注明附件名。
- 用户**没有**（常见）→ 不要出现参考图字样，改成条件式：`产品外观按 <具体描述>；若我另附图则以图为准`。缺具体描述时用参数行占位：`[[待确认: 产品外观=按品类通用描述]]`。

## 二、生文

| 用 | 不用 |
|---|---|
| 交付物 + 读者 + 用途 + 结构 + 长度 + 语气特征 | "写得专业点""接地气一些" |
| 可检查的结构约束（分几节、每节写什么、要不要标题） | 只给一个总字数 |

骨架：

```text
任务：产出 <交付物>，用于 <用途>
读者：<谁>，已知 <背景程度>，关心 <什么>
结构：<分节/分点方式>，每部分写 <什么>
长度：<字数或篇幅>
要求：<必须包含的信息>；<语言与语气特征>
输出：<Markdown/纯文本>，<是否需要标题>
```

范例：见 `prompt-templates.md` §五（数据分析清单），以及本文档 §四 的跨域范例。

要点：读者决定详略与解释深度，**不要给一个泛泛的"专业"**；如果用户给了范文，写成"模仿以下范文的结构与语气：<粘贴>"。

## 三、生成代码

| 用 | 不用 |
|---|---|
| 语言+版本、运行环境、交付形态 | "写个脚本" |
| 接口签名/调用示例、输入输出样例 | 只说"处理一下数据" |
| 不可改动的现有部分、依赖策略、错误处理、验收方式 | 一句"要健壮" |

骨架：

```text
任务：实现 <交付物>
环境：<语言与版本>，<框架>，<运行平台>
接口：<函数/端点签名>；输入 <样例>；输出 <样例>
约束：不改动 <文件/签名>；依赖 <允许/仅标准库>；错误处理 <返回错误/抛出>
验收：<能直接跑 / 附可运行示例 / 通过现有测试>
输出：<单个文件/多个文件>，<语言注释风格>
```

范例（原文："帮我写个脚本处理一下日志，要健壮"）：

```text
任务：写一个命令行脚本，统计 Nginx access.log 中每个 IP 的请求数和 4xx/5xx 占比，输出 Top 20。
环境：Python 3.12，标准库；Linux 上运行，UTF-8 输入。
接口：脚本入口 `python top_ips.py <logfile> [--top N]`，默认 N=20。
输入样例：`127.0.0.1 - - [10/Oct/2026:13:55:36 +0800] "GET /api HTTP/1.1" 404 123`
输出：Markdown 表格，列 = IP | 请求数 | 4xx | 5xx | 错误率，按请求数降序。
约束：仅用标准库（不引入 pandas）；文件不存在或无匹配行时打印明确错误到 stderr 并以非 0 退出，不抛裸异常。
验收：给出运行命令与一份 3 行的输入/输出示例。
输出：单文件 top_ips.py，含简短中文注释。
```

要点：**"健壮"必须落成具体行为**（错误码、stderr、退出码）；不确认依赖策略时默认"仅标准库"并标【暂定】；不可动部分要单独一行，防止 AI 顺手重写。

## 四、跨域范例（代码 + 文档）

用户原话："写个接口，顺手把文档也写了。"

处理：按 §三 提问（栈 + 接口边界），把文档写成输出契约的一部分：

```text
任务：实现用户查询接口，并附带接口文档。
环境：Node 20 + Fastify；运行在 Docker 内。
接口：`GET /api/users/:id` → 200 返回 `{ id, name, email }`；404 返回 `{ error: "not_found" }`。
约束：不改动现有 `src/db.js` 的导出签名；不新增运行时依赖。
输出：
 1. `src/routes/users.js`（新增路由，含输入校验）
 2. `docs/api/users.md`（端点、参数、返回示例、错误码表）
验收：给出 curl 示例；404 分支必须单独列出。
```
