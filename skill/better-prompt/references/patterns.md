# 内置优化机制库（检索不可用时的兜底）

联网检索失败或用户要求跳过检索时，从下表取机制，用法与联网采纳完全相同：**采纳 ≤2 条，每条必须落到加/改/删的具体动作**。

⚠️ **采纳表只列会改变终版提示词内容的机制**。本 skill 自身的流程规则（提问预算、长度闸门、改动白名单、三档标注、采纳上限）**不是机制，不要列进采纳表**——它们本来就一直生效，列进去等于把流程当成果。（"负面约束单列""接口契约"这类会改变终版某一行的，才是机制。）

## 一、机制表

来源标注为调研到的同类项目类型（`as_of 2026-10`），只取通用结构性机制，不依赖具体工具链。

| 机制 | 一句话说明 | 适合补的缺口 |
|---|---|---|
| 提问预算 | 每轮限制问题数，把提问当稀缺资源 | 防止问题疲劳 |
| 每题必答"改变了什么" | 说不出改变哪句就不问 | 砍掉无效问题 |
| 白话复述确认 | 先复述"你要的是…"再生成 | 防止理解偏差 |
| 四层结构 | 指令/情境/参考/输出分层 | 长任务结构混乱 |
| 两段式收缩 | 短任务只用目标+输出格式 | 防止模板注水 |
| 输出契约 | 明确格式、长度、结构、验收 | "随便写写"式输出 |
| 三档来源标注 | 已确认/暂定/待确认 | 防止把猜测当事实 |
| 条件式指令 | 若 X 则 A，否则 B | 用户自己也没定的事 |
| 显式占位符 | `[[待确认: 字段=默认值]]` | 替代 `[填写]` 假澄清 |
| 渐进披露 | 模板库按需加载，不全塞进上下文 | 控制 token |
| 反模式清单 | 先列出要避开的做法 | 防止只改词不改目标 |
| 原文够好即不改 | 明确允许"无需修改"的结论 | 防止为改而改 |
| 单场景约束 | 一条提示词只管一件事 | 防止全能超长提示词 |
| 长度闸门 | 终版 ≤ 分域字数上限（生图 300/生文 800/代码 1200 字） | 防止膨胀 |
| 独立复核 | 输出前用一句话自查是否偏离原目标 | 防止跑偏 |
| 负面约束单列 | "不要什么"与"要什么"分开写 | 生图去掉不想要的元素 |
| 接口契约 | 写明签名、输入输出样例 | 生成代码对接不上 |
| 错误分支枚举 | 失败路径逐条给出行为 | "要健壮"不可验收 |
| 可运行示例 | 要求附跑通命令与样例 | 拿到代码不会用 |
| 版本锁定 | 写明语言/框架/模型版本 | 生成的东西跑不起来 |
| 参考图保持项 | 明确哪些元素必须不变 | 生图改图跑偏原设计 |

## 二、反模式（作为"要避开"的固定内容）

1. **只改词不改目标**——把"写个总结"改成"你是资深分析师…"，词变多、目标没变。
2. **全能超长提示词**——换场景就废；可复用的提示词往往短、只管一件事。
3. **统一模板**——所有请求套同一骨架，输出千篇一律。
4. **自造样例**——编一个"更好的例子"掩盖真实短板。
5. **问题疲劳**——一次抛十几个问题，用户比原来更不知道怎么答。
6. **把不确定编成事实**——用户没说的受众、预算、平台直接写成确定值。

## 三、记录格式

使用内置库时，第 2 步的采纳表照常输出，把来源列写成 `内置#<机制名>`，并注明 `检索不可用`。
